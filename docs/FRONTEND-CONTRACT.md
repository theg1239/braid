# Frontend contract

The UI uses dark Cloudflare Kumo components, Phosphor icons, and locally served Geist fonts. Repository tabs are Code, Pull requests, Agents, and Settings. Use GitHub's words for their controls.

The API calls a pull request a `change` under `/api/changes`. It calls a task a `mission` under `/api/missions`. `shared/types.ts` defines repository data. `shared/account.ts` defines accounts. `shared/questions.ts` supplies review questions and policy descriptions. See the [product model](DESIGN.md).

## Routes

Repository addresses use `/:owner/:repo`, from `shared/routes.ts`. `example` is reserved for `/example/relay`. The URL selects the repository through `GET /api/repos/:owner/:repo` or the signed-in account's owner data. Repository requests carry its ID as `X-Braid-Workspace: <workspaceId>`.

Public repositories allow signed-out reading. Write controls explain required sign-in with `Sign in to …` tooltips. Unknown and inaccessible private repositories return the same 404. Standalone owner-key deployments use flat routes under `/`.

### Home, profiles, and imports

The dashboard groups pull requests into Needs your review, Returned to you, Merging, and Recently merged. Recently merged contains at most 8 results from the last day. Rows show title, repository, number, model, owner, and time. Review counts appear in the tab title and favicon.

The dashboard also lists personal and organization repositories with visibility. Owners get New repository. Profile visitors see public repositories. People see all their own repositories. Organization members see their organization's repositories. Empty personal profiles remain public.

Unknown organizations and organizations without public repositories return the same 404 to visitors. Personal profiles have no Teams, People, or invitations.

Imports retain the name and visibility selected at creation. A GitHub `202 { importing }` response with `preview` shows source files immediately. A source and elapsed-time bar remains until Braid's copy replaces them. URL imports show their source and elapsed time.

Stopped imports offer Try again through `POST /api/project/import/retry` or Choose another. The branch menu follows `project.branches` as copying completes. `tree/<branch>` opens each branch.

### Code and blame

The Code menu shows the public clone address, signed-in setup prompt, MCP endpoint, and CLI connect command. It never shows tokens.

If a commit read fails, the Code page's commit column shows **Couldn’t load commits · Retry**.

Blame uses `GET /api/blame`, cached per head in `src/lib/resources.ts`. Line ranges show model or person by `@login`, owner, age, and an `inferred` label when applicable. A hover/click card shows commit subject, hash, model, owner, tool, session, fleet, pull request, task, and confidence.

Confidence labels are Seen by Braid, From the commit, and Inferred from the commit. A summary shows contributors and line counts. The response's `note` explains coarse attribution or history limits. Combined tasks use file-specific authors.

Live blame supports the default branch. The example also supports its recorded branch. Only nearby ranges render, at their exact offsets.

### Pull request list

The queue summary links to `/queue`. Empty queues get one short line. Paused or disabled queues show a reason and Resume for owners.

Rows use one state icon, title, server `label`, number, time, and author. Queued or merging state follows the author. Counts use `+N −M`. `checkState` supplies a text link to Checks. The pull request state is the only state icon of the row.

Stacks show an icon and position, such as 2 of 3. Waiting dependencies read Waiting on #51.

### Conversation and proof

Current-revision proof follows the description. Desktop and phone screenshots appear together with their source. Enlarged images support arrow keys. An earlier revision of the same page can appear beside the image.

Command rows show state, command, duration, and execution source. Failed output opens by default. Other output stays folded. Earlier revision commands appear under a folded summary.

The timeline contains reviews and conversations. Add a comment supports Markdown and ⌘Enter/Ctrl+Enter. Resolved conversations fold behind Show conversation. People can resolve or reopen them. A comment alone does not request changes.

The merge box has review, checks, proof, and conflicts rows. Expandable rows show reviewers, check states, pages, and commands. Proof summaries identify passed commands or a failed command. Questions offer Approve and merge, Request changes, or Close pull request.

Request changes starts with `suggestion`. Live owners can select Add as an instruction for every agent. The instruction request follows the review. Other users see its disabled reason.

Depends on, Required by, and stack position appear in the header. Unmerged dependencies appear in the merge box. A prerequisite closed without merging requires an owner decision. The available actions request changes or close the dependent pull request.

Reviewer verdicts use one sidebar icon each. Returned pull requests read Changes requested with their reason once. Checks and conflict rows identify their own failures.

### Checks and files

Braid checks include repository commands, Dependency review, and Code security. Security rows use `guards` for credentials, test edits, dependency edits, and instruction findings. They never show the secret. Instruction findings identify the blocked string, location, and instruction.

GitHub checks include Actions, CodeQL, and review-app waits. CI rows use `source: 'ci'` for statuses on the merge-queue commit. Queue views compare `ci.required` with `ci.statuses`: passed, running, failed, or waiting.

Files changed keeps Viewed state per pull request, revision, and path in the browser. Unified/Split preference also persists. Narrow screens put the tree behind Files. Off-screen diffs retain their height.

The revision picker offers All changes, Since first push, or Since push N. `GET /api/changes/:id/compare?since=N` supplies files and counts, including reverted edits. `GET /api/changes/:id/diff?since=N&path=PATH` supplies each diff.

Selecting a line number opens a focused comment form on that side. Cancel returns focus to the line. Conversations track unchanged lines across revisions or show Outdated with their original line. Resolved conversations can expand. Returned conflicts appear first with Git-style regions.

Queue stacks show dependencies in order, including merged prerequisites. History menus offer Revert for each pull request, with access reasons when disabled.

### Agents and tasks

Every tour page shows one **Recorded** label. Replays show no run label.

The composer shows repository, branch, brief, execution choice, and Start. Fleet authors use the model and `for @owner`. Task rows show title, agents, files, `+N −M`, age, pull request, and one state label.

The fleet groups model, owner, and tool. Merged, Lines added, and On main always appear. Sent back, Reverted, and Open appear when any row has a nonzero value. Surviving lines determine order. The fleet excludes simulated load from the queue simulator. Rows link to `/pulls?agent=ID`.

Owners can steer running tasks through `POST /api/context` with the task ID. Instructions appear in Activity. Connected agents receive them on checkout or `braid task resume`. Hosted agents read them at the next checkpoint.

Agent rows show model, owner, assigned connection, focus, counts, copied commit hash, time, and state. They expand to show results. Activity lists steps with one state icon each. Local tasks can select 1–3 work connections for this repository. Only those connections can claim the task.

**Compare code** keeps 3 one-line excerpt slots for each version, so its controls stay in place.

## Vocabulary

`progressOf` supplies GitHub-style progress labels. `pullState` maps 7 internal states to Open, Merged, or Closed. Internal merge terms stay out of primary views. Color marks state, not decoration. Do not use status dots.

`authorLine` and `AuthorChip` display model and owner, such as “Claude Opus 5.5 for @maya-chen”. The compatibility field `owner.github` carries the Braid username. Imported history can retain its available name. Conversations also show the tool.

`kind:'bot'` displays the automation name without an owner byline. Bots have separate totals and no fleet entry. Agents and pull request authors have no avatars or monograms. Personal profiles and account menus can use linked GitHub avatars.

## Data

The account read starts before React renders. Repository resolution starts `/api/state` and route reads without waiting for the account. Hover, focus, or touch starts linked screen code and data. The shell excludes screens. Likely screens preload during idle time.

Early CSS preloads fetch bytes only. Vite applies and awaits styles before rendering a screen. Failed imports remain failed until Reload.

The repository store polls `/api/state`, faster during task execution. `src/lib/live.ts` shares one request per resource across screens. Resources include pull requests, queue, policy, simulated agents, and owner-only `/api/hooks`. Missing hooks return `null`. Hook secrets never appear.

Visitor polling has a 30 s floor. Starting a write lifts it for 1 min through `src/lib/polling.ts`. Header counts, Code notices, and pull request lists share the `attention` page. Lists use the server's `label` without rewriting reasons.

Evidence sources are `braid`, `github`, `ci`, and `agent`. Agent reports never become verified passes. Recorded example edits, reviews, and command results are scripted. Its screenshots are real renders.

Revision `evidence` contains screenshots and command results. `changes.evidenceImageUrl` supplies `GET /api/changes/:id/evidence/:image`, with `?workspace=<id>` when needed. Images use session-cookie authorization because `<img>` cannot send `X-Braid-Workspace`. Proof images load lazily. Enlarged images load eagerly. Failed images keep their frame and show Not available.

`GET /api/instructions` returns `{instructions, errors, head}` from main. `GET /api/policy` includes the same `instructions`.

### Public capabilities

Nonmembers receive `mode:'live'`, viewer role, `canWrite:false`, and `authenticated:false`. They have no identity or demo cookie. Snapshot `files` is empty. Code comes from repository endpoints.

Permitted Git content and paths remain verbatim. Braid metadata removes emails and secrets. Secret-bearing revisions return `withheld:true` without content in diffs, tasks, or integration previews. Responses omit credentials, webhooks, and internal remotes. Optional fields can be absent.

Visibility leases last 5 s. Forced-private imports wait for expiry. Writes and sensitive reads require membership. `X-Braid-Workspace: demo` keeps recorded-example behavior.

Limits:

- 300 reads/min per network, including 304 responses.
- 60 expensive reads/min per network.
- 30 cold builds/min per repository, including at most 10 from one network.
- Cold-budget exhaustion returns 503 with `Retry-After`.
- Visitor polling follows the 30 s floor and 1 min write window without attention reads.

## Code rendering

`@pierre/diffs` renders files, diffs, and conflicts in `src/components/code/`. Shiki uses its JavaScript engine. Grammars in `src/lib/shiki.ts` load on demand or through route preloads. Rendering virtualizes against page scroll.

Inputs up to 200 lines and 12,000 characters across both sides first render plain rows. Highlighting then runs on the main thread. Larger inputs and conflicts use workers.

The viewer loads on first use or link hover. Markdown uses a separate `src/components/code/markdown.tsx` chunk with `marked` tokens. Raw HTML never renders. Links allow HTTP(S), same-page, or relative targets.

Limits from `src/lib/diff.ts`:

- Above 5,000 lines or 200 KiB, offer download and a plain-text override.
- The override supports up to 20,000 lines and 1 MiB.
- Larger files allow download only.

### Dependencies

`dependsOn` accepts at most 16 positive pull request numbers or internal IDs from this repository. Omission on revision retains dependencies. `[]` clears them. Cycles and closed prerequisites return 409. Unknown or other-repository IDs return 404. A stack contains at most 128 pull requests.

An eligible dependent stays open until prerequisites merge. Responses can include `dependsOn`, `requiredBy`, and `waitingOn` references with `id`, `number`, and `status`. The stack field is `stack: {position,total}`. `/api/queue` includes ordered `stacks`.

Known pushed heads infer dependencies when `dependsOn` is absent. Local and hosted task submissions accept the same field. Task checkout `pullRequest` context includes state, next action, dependency references, and `outdated` prerequisites.

CLI submission uses `braid submit --depends-on 51,52`. `none` clears dependencies. The task helper uses `change submit --depends-on`. MCP uses `depends_on`.

The UI shows changed prerequisites with Restack. CLI restacking uses `braid restack <n>`. MCP uses `restack_pull_request`. `/api/queue?stackCursor=N` returns 20 stacks per page with `nextStackCursor`.

### Recorded writes

The example accepts per-visitor approvals, requested changes, closures, and review conversations. Approved pull requests progress through queued, merging, and merged states. Their merge event states that no checks run.

Every New task replays the sample. Live-only actions return 409 with matching disabled-control reasons. Settings Reset clears visitor answers. Standalone deployments without a session also select the example.

## Account

Fetch `/api/account` alongside route reads. Provider `github` supports GitHub, email, and passkey sign-in. Provider `owner-key` retains standalone Account settings.

Organization members can read repositories. Owners and team members with Write grants can write. Organization administration remains owner-only. `readOnlyReason` in `src/store/workspace.tsx` supplies disabled-control explanations. A repository 404 means it is unavailable to this viewer.

MCP uses streamable HTTP at `/mcp`. A client with OAuth needs only the address. Other clients send `Authorization: Bearer <access token>` and `X-Braid-Workspace`. Settings shows this endpoint.

Sign-in, username setup, invitations, agent approval, and OAuth consent use `src/account/`. See [agent onboarding](AGENT-ONBOARDING.md) and [architecture](ARCHITECTURE.md).

GitHub authorization and access changes retain the initiating page, query, and anchor in the server-side one-use flow. Return locations must be local paths.
